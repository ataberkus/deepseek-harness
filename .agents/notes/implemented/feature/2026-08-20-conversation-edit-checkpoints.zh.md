# Agent Note: Conversation edit checkpoints

Status: implemented

[English](2026-08-20-conversation-edit-checkpoints.md) | 中文

## Problem

编辑已结算的用户消息时，需要从该回合之前的文件状态重新运行对话。会话历史只追加，而文件系统会变化，无法仅从对话日志重建。

## Decision

`WorkspaceCheckpoint` 负责内容寻址的工作区快照、带日志恢复、紧急快照、恢复标记、租约和保留策略。捕获消费者记录初始文件树与已结算回合边界，并在要求恢复时阻止模型和顶层工具工作。

`session.edit` 会校验已结算的直接用户消息、其前置的 ready 检查点、源会话空闲状态和工作区归属。它保存紧急快照、恢复所选文件树、从被编辑回合之前的前缀创建子会话，在持久会话旁车中记录源／所选／紧急／子会话关系，并只把替换消息排入子会话。`session.activate` 为处于空闲状态的会话恢复最新可用的非紧急检查点。

编辑操作会把持有的工作区租约传入子会话的初始检查点捕获。本地提供方将匹配的捕获租约视为该操作内可重入，因此事务保持独占性，同时不会等待自身释放租约。

`session/checkpoints` 投影携带检查点行、操作阶段、已应用与恢复状态、所选分支标签及工作区可恢复性。Web 客户端会在 Session 创建前保留该基线，只为符合条件的直接用户消息显示**编辑并重新运行**，并在工作区无法恢复时保留可读对话、报告诊断。

## Alternatives considered

**原地修改源日志。** 这会破坏原始记录并使编辑前的工作区关系变得含糊，因此编辑创建子分支并保持源日志只追加。

**只 fork 对话而不恢复文件。** 仅有日志分支会让工具及后续回合处于错误的文件系统状态，因此在发布子会话前恢复所选检查点。

**把文件字节存入会话事件。** 这会扩大日志，并让每个历史消费方接触工作区数据，因此清单与 blob 保留在提供方的 storage domain 和对象库中。

**把不可用检查点当作空工作区。** 静默丢失文件会使重新运行不安全，因此不可用树仍可阅读，但在可用恢复之前禁用新的工作。

## Consequences

编辑会保留两个对话分支，并为恢复编辑前工作区提供持久的紧急路径。检查点元数据是旁车而不是模型可见的会话历史，因此客户端可以重新连接并看到分支与恢复诊断，而不会收到文件内容。本地提供方要求 storage-domain 后端，并由 invariant companion 报告跨记录关系错误。这重新引入了[移除用户消息编辑占位](../simplification/2026-07-31-drop-user-message-edit-stub.md)中去掉的已结算消息编辑入口，现由检查点恢复和子分支支撑。

## Testing

服务、提供方、租约、恢复、保留策略、Host RPC、wire schema、运行时投影、输入状态和浏览器组件测试覆盖检查点与编辑路径。组装后的 Web snapshot suite 覆盖真实 Host/client 传输、编辑入口、分支标签、恢复诊断、子会话执行和重连投影。
