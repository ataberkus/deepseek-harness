# Agent Note: Model favorites

Status: implemented

[English](2026-09-12-model-favorites.md) | 中文

## Problem

部署会跨多个提供方公布数十个模型，而 composer 模型位与 `/model` 弹窗都按提供方分组顺序列出它们。在两三个模型之间来回切换的用户每次都要滚过整个目录。

## Decision

`dsh-client-ui-model-selection` 将一份浏览器本地收藏列表置顶于两个选择入口。`ModelDirectoryResolver` 持有唯一一份持久化的 `ModelFavoritesState` 存储（`localStorage` 中的 `dsh.modelFavorites.v1`）；composer 模型位与 `/model` 弹窗读取同一实例，因此在模型位中切换星标后，弹窗下次打开即按新顺序排列。模型位先渲染收藏分组，每行带星标切换（`favorites.title`、`favorites.add`、`favorites.remove`），同时收藏的模型仍保留在其提供方分组中并显示实心星标；弹窗按目录顺序先排收藏行，再排其余模型，最后排提供方失败行。收藏 id 为 `provider/model` 字符串；未知 id 保留在存储中但从不列出，畸形的存储值重置为规范化后的列表。收藏是仅影响呈现的视图状态：从不进入会话日志、`session.selectModel` 负载或模型请求。

## Alternatives considered

**宿主侧设置命名空间。** 未采用，因为收藏是与草稿和面板宽度同类的按浏览器视图状态，不是按部署配置；宿主命名空间需要新的设置 schema、提供方和设置界面，而该偏好必须在只读的非 loopback 客户端上可用。

**按会话收藏。** 未采用，因为置顶模型是用户的属性，不是会话的属性；按会话作用域需要在每个新会话中重新加星，并为每个被删除的会话遗留存储键。

**在 `/model` 弹窗内切换星标。** 未采用，因为 popupSelect 外壳拥有其行且不提供每行操作插槽；为模型收藏教会共享外壳业务特定的切换，会将每个 popupSelect 消费者与模型收藏耦合。

**将收藏模型从其提供方分组中移除。** 未采用，因为提供方分组是完整的目录视图；从分组中隐藏模型会使分组看起来不完整，并隐藏用户发现该模型位置的取消收藏入口。

## Consequences

- 在少数模型之间切换无需滚动：收藏在两个入口中始终置顶，弹窗顺序随模型位的切换即时更新，无需重新加载。
- 收藏按浏览器在重新加载后保留，从不跨设备泄漏；非浏览器运行时保持空的内存列表。
- 未知或畸形的存储 id 不会破坏选择器：它们被跳过或重置，选择仍使用提供方／模型／推理强度 id。
- 单元覆盖拥有 id 规范化、切换顺序、按目录顺序列出、存储持久化与重置、经共享服务的弹窗排序，以及模型位收藏的加星、筛选与从收藏分组选择。
