# 会话编辑检查点

[English](2026-08-19-conversation-edit-checkpoints-design.md) | 中文

状态：供审阅的草案

## 范围

本规格为 Web 会话增加类似 Cursor 的编辑并重新运行行为。用户可以选择较早的直接消息，编辑其文本，并从该消息之前的工作区状态发送修改。修改后的运行成为活动子分支，而原始会话及其工作区检查点仍可恢复。

此功能会为会话历史和会话工作区内的文件建立版本。它不会为任意主机文件建立版本，不会撤销网络或数据库影响，不会停止或反转已部署资源，也不会提供通用工作流和任务检查点。

## 当前约束

`Session` 是追加专用的事件日志。现有会话存储可以从包含指定事件的边界为活动会话创建分支，且分支边界必须在已完成轮次处结束，不能位于开放轮次内部。现有会话检查点策略会在模型和工具边界前持久化刷新日志事件，但不会捕获工作区文件，也不会提供面向用户的恢复点。

Web 客户端在浏览器运行时保存业务状态，并通过插槽和存储组合展示内容。Host 负责会话变更和文件系统权限。具体 agent loop 必须保持不变；编辑行为属于检查点能力、会话编辑消费者和客户端插件。

## 目标

- 捕获初始工作区检查点，并在每个已结算轮次后捕获一个检查点。
- 将每条直接用户消息关联到其轮次之前的检查点。
- 用户发送编辑后的消息时自动恢复该检查点。
- 在新的子会话中从编辑后的消息继续运行，同时不在活动分支中显示被丢弃的后续消息。
- 保留原始会话、其后续消息和其检查点，以便恢复和比较。
- 让发送前的取消不产生副作用，并让恢复和分支创建在失败后可恢复。
- 支持编辑文本，同时保留现有附件块；第一版对不支持的内容块禁用编辑。
- 让检查点存储在重启后仍受限且持久，并独立于 Git 历史。

## 检查点模型

检查点是持久化的控制面记录，包含不透明的 `CheckpointId`、会话 id、工作区身份、所代表的会话包含边界、可选的父检查点 id、分支元数据、捕获状态、创建时间、清单哈希和内容寻址的文件引用。

`Checkpoint 0` 表示第一轮之前的工作区。后续每个检查点表示一个已结算轮次及其会话持久化刷新完成后的工作区。面向用户的标签按分支顺序生成；运行时使用不透明 id 和序列边界。只有当清单和元数据都持久化后，检查点才可被选择。

清单以会话 cwd 为根，记录相对路径、文件类型、支持时的模式、大小和内容哈希。普通文件内容存放在 Harness home 下的本地内容寻址对象存储中，元数据存放在专用存储域中。提供方不会跟随符号链接。可以记录安全的链接项；含有不支持或不安全项的检查点不能自动恢复。排除项和存储限制必须是明确的提供方设置。

检查点元数据不是会话事件，因为它不是模型可见的会话数据。子会话仍通过现有会话分支和 seed 机制接收权威的继承事件前缀。父会话谱系仍在会话头中保存；检查点记录补充工作区和编辑关系，不改变消息投影。

## 轮次捕获

检查点消费者监听已结算轮次和持久化扩展点。当会话获得工作区时，它捕获初始状态；每个 `turn/end` 之后，在前一批会话事件完成持久化刷新后，它捕获下一个状态。如果能够获得稳定的工作区状态，已完成、失败、取消和中断的轮次都包含在捕获中；检查点状态记录轮次结果。

对于普通模型工作，工作区捕获采用软失败。捕获失败不会删除已完成的响应，也不会阻止后续用户消息，但在可用检查点出现前，受影响的消息没有编辑操作。Host 和浏览器运行时会将失败公开为检查点诊断，而不会无提示地声称状态可恢复。捕获期间发生并发写入时，系统会重试或报告不可用，而不是生成可能不对应单一文件系统状态的清单。

捕获消费者不把后台进程视为可撤销的轮次部分。轮次结算后发生的文件变化只会进入之后的一致检查点或显式恢复快照。工作区租约防止恢复编辑与 agent 正在拥有的操作竞争。

## 编辑事务

编辑是两个阶段的用户交互：

1. 客户端进入草稿模式，将选中的直接用户消息复制到现有 composer 状态中。此时不修改检查点、文件或会话。
2. 发送操作向 Host 命令提交会话 id、消息身份、编辑后的文本、保留的附件块和选中的检查点引用。

Host 命令验证消息是已结算轮次中的直接用户消息，源 agent 处于空闲状态，检查点属于同一会话谱系和工作区，并且编辑后的负载有效。命令将分支边界解析为选中消息之前紧邻的已完成 `turn/end`。编辑第一条消息时，因为它之前没有源事件边界，所以创建带有明确父会话元数据的空 seed 子会话。

在改变工作区前，命令捕获当前文件的紧急检查点。随后获取每个工作区的租约，暂存目标清单，验证每个对象和包含规则，并通过回滚日志应用恢复。文件系统提交开始后，取消操作会等待事务完成或回滚。恢复成功后，命令通过现有分支和 seed API 创建子会话，使用源组合创建其 agent，并接纳编辑后的用户消息。

子会话头记录普通的父会话和 seed 长度谱系。检查点旁路记录源会话、源边界、选中的检查点、编辑后的消息和紧急检查点。只有恢复成功且子会话发布成功后，子会话才成为活动会话。如果暂存、验证、恢复或子会话发布失败，日志会恢复原始文件系统，源会话保持活动状态。如果子会话已经发布而其后续模型调用失败，子会话保留为失败分支，原始会话不受影响。

用户切换到旧分支时使用相同的事务。活动工作区始终对应所选分支最新的可用检查点。如果所需对象已被驱逐，或工作区不再满足清单，分支会显示为不可用，而不会在无关文件上恢复运行。

## GUI 行为

具有可编辑文本和可选保留附件的已结算直接用户消息显示 `Edit & resend` 操作。进行中的消息、注入上下文、steering 消息、目标轮次、合成通知以及含有不支持内容块的消息不显示该操作。

编辑横幅说明运行从指定检查点开始，并显示计划恢复的文件数量。它提供 Cancel 和 Send 控件。Cancel 退出草稿模式，不读取或写入检查点存储，也不改变工作区。Send 显示准备、捕获紧急状态、恢复文件、创建分支以及就绪或失败等实时操作状态。

Send 成功后，子会话记录从继承前缀开始，包含编辑后的用户消息，并不包含原始消息或源会话之后的任何后续消息。侧边栏和会话谱系视图仍保留原始分支。每个分支显示自己的检查点标签和当前工作区关联。操作失败时保持源会话被选中，并显示可采取行动的诊断，不伪造成功的子会话。

`ui-conversation` 负责编辑操作、草稿状态和横幅。浏览器运行时负责普通的检查点和操作快照。Host 负责授权、工作区租约、恢复、分支创建和持久化元数据。第一版不增加独立的 Trajectory 检查点编辑器；后续视图可以消费同一个运行时投影。

## 存储与安全

本地提供方在 Harness-home 权限下存储检查点元数据和内容对象，并使用内容哈希去重相同的文件内容。保留策略和总字节数限制是明确的配置。驱逐不能删除活动分支引用的检查点；如需处理此情况，必须将分支标记为不可用并保留诊断关系。紧急检查点遵循同一策略，并带有面向用户的恢复关系。

所有恢复路径都强制执行规范化的工作区包含关系，拒绝路径穿越，验证对象哈希，并避免跟随工作区外的符号链接。暂存和回滚覆盖文件创建、替换、删除、重命名重建和元数据应用。回滚失败时，工作区被标记为需要恢复，并在用户或恢复命令处理前阻止新的模型工作。

检查点恢复不承诺外部影响的精确一次语义。之前的工具可能已经改变远程服务、数据库、终端进程或被忽略的外部目录。UI 将保证明确称为工作区文件恢复，不暗示整个外部世界被回退。

## 组合与接口

该能力族包含负责检查点元数据、捕获、检查、恢复和保留的 Service Definition；负责 Harness-home 存储和文件系统快照的本地提供方；以及负责轮次捕获、编辑命令和客户端投影的消费者。替换提供方不会改变会话分支语义或面向模型的工具注册。

编辑命令是 Host 负责的用户操作，不是面向模型的工具。它在取得权限前检查已认证的会话所有者和活动工作区。浏览器通过现有 Host 连接接收操作进度，并从不可变的运行时快照渲染。检查点内部信息不会进入系统提示或派生的模型历史。

第一版实现应增加检查点族、本地提供方、轮次和编辑消费者、Host 远程约定，以及 Web 运行时和会话 UI 部件。它应复用现有的会话持久化、会话分支、agent 创建、工作区身份、连接、插槽和存储机制，而不是增加平行的会话或 UI 状态系统。

- 为暂存、紧急检查点、回滚、缺少对象、超出配额、并发写入、工作区租约以及提交前和提交期间的取消操作编写单元测试。

- 验证编辑第一条消息会恢复 `Checkpoint 0`，编辑后续消息会恢复前一个检查点，子会话模型历史会排除被替换消息及其后续内容，而父会话保持不变。
- 为编辑、取消、进度、失败、分支选择、附件保留和需要恢复的状态增加 Host 与 Client 测试。

- 运行聚焦的包测试、`pnpm run test:gui`、受影响的构建、`DSH_SNAPSHOT=replay pnpm run test:web` 以及要求的文档和差异检查。

## 非目标

此功能不会创建 Git 提交或引用，不会删除原始会话，不会重写追加专用事件日志，不会恢复会话 cwd 之外的任意文件，不会撤销外部影响，不会为运行中的后台任务建立检查点，不会恢复部分执行的工作流，也不会将检查点选择暴露为面向模型的工具。

## 已考虑的替代方案

- **仅创建会话分支：** 拒绝，因为编辑后的运行会继承被丢弃后续内容产生的文件变化，无法从任务中选定的点重现。
- **使用 Git 作为检查点：** 第一版拒绝，因为工作区不一定是 Git 仓库，被忽略的文件会不完整，隐藏提交或引用会改变用户 Git 状态。
- **破坏性截断日志：** 拒绝，因为会话日志是追加专用的，并且保留原始分支可以在不削弱持久性的情况下提供恢复和比较。
- **仅在确认对话框后恢复：** 不作为默认行为，因为 Send 已经是用户明确的提交决定；自动紧急检查点和可见的恢复范围无需第二个阻塞式提示即可提供恢复能力。
- **将编辑逻辑加入 `agent-loop`：** 拒绝，因为 loop 已经通过会话分支、agent 创建、生命周期和事件扩展点提供能力；将工作区和 UI 策略嵌入其中会使具体驱动不可替换。

## 风险与缓解措施

检查点捕获可能消耗存储，并延迟编辑操作可用。内容寻址对象、明确的保留策略、带不可用状态的异步捕获以及可见的检查点就绪状态可以在不阻塞已完成模型工作的情况下限制成本。

恢复可能替换用户在选定检查点之后创建的未提交工作。自动紧急检查点、可见的文件数量、分支保留和可恢复的操作诊断提供了回退路径，同时保留所要求的自动行为。

工作区可能被多个进程或外部编辑器共享。本地租约和捕获后的清单验证可以阻止已知的进程内竞争；跨进程协调留在第一版之外，并且必须报告恢复冲突，而不能无提示地覆盖并发工作。

子分支可能包含有效的会话，但其检查点会因保留策略或文件系统变化而不可用。因此，分支导航必须区分会话可用性和工作区可恢复性，并拒绝运行无法恢复所需文件状态的分支。
